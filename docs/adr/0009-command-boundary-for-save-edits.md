# Route every Save mutation through tested editor commands

The Swing UI currently mixes widget events, raw database traversal, and Save mutation, making it possible for a visually correct replacement to dispatch an incorrect edit. Compose screens will consume immutable UI state and issue editor commands; they will not manipulate `DBList` structures directly. Each command records its semantic change and evidence level—verified in-game, structurally verified, unverified, or deliberately dangerous—so validation, warnings, Undo, the pre-save review, and tests share one source of truth.

Every command that mutates a Save requires a deterministic committed-fixture test that executes the command, writes a working copy, reloads it through the parser, asserts the intended semantic result, checks archive-entry key equality, and proves every untouched entry byte-identical. CI must not skip supported mutation families. Compose semantic tests verify command wiring, a small packaged-app suite verifies critical workflows, and representative working copies are checked in-game before a mutation family is called verified. Kover supplies report-only coverage initially; risk and missing scenarios, not a global percentage, drive new tests.
